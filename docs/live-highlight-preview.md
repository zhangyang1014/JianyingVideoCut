# 直播产品集锦试看

## 工作流程

1. 在产品集锦卡片点击「快速试看」，直接从源视频播放本条集锦的选段，无需生成预览文件。
2. 播放会跳过未入选内容，在本条结尾自动停止。连续入选语句之间保留自然停顿；选段以当前集锦快照为准，与渲染导出的处理一致。
3. 需要检查精确切口时，使用卡片右侧的「渲染预览」。它使用 1280 长边上限的预览画质，不烧字幕；字幕和最终画质仍在最终导出中核对。

快速试看通过浏览器跳转源视频，适合核对内容与选段，不作为精确音频接缝或最终画质的验收结果。

## 等待与缓存

- 同一源视频、选段和预览设置的同时请求，共享一次渲染。一个本地服务最多同时渲染两条不同预览。
- 缓存指纹包含源文件路径、大小、修改时间、完整任务 ID、片段边界、保留动作及预览档位。替换源视频或修改切点后重新渲染。
- 命中缓存仍通过基础媒体校验；不可读、缺少音视频流、时长异常或非有限时长不作为有效预览使用。
- 「取消等待」停止本页等待和后续自动播放；已开始的共享渲染继续完成，供其他请求和缓存使用。
- 切换集锦、切换质检版本或开始快速试看后，旧请求的响应不能抢占当前播放。主动结束试听也不会误报播放失败。

## 选段契约

`POST /api/tasks/{task_id}/export/clip-preview` 优先读取 `reel_id` 和 `quality_stage` 指定的服务端快照；客户端附带的 `segment_ids` 仅用于兼容没有 `reel_id` 的旧请求。

canonical 预览与导出共用来源校验：不允许引用缺失语句、越出产品范围或打乱源时间顺序。基于旧内容版本的集锦返回 409，引导更新集锦；不能静默丢掉失效语句后播放残缺版本。

旧接口的片段数组同样拒绝缺失、重复和无效时间范围。正常响应继续返回 `url`，并附带 `cached` 和 `render_profile`，兼容原有播放器。
