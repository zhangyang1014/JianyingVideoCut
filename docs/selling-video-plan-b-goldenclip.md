# 执行方案 B：在 GoldenClip 内建设卖货视频创作与一键剪辑

状态：首版已实施（2026-09-19）。项目、资料、创意、分镜、素材分析与一键成片链路已落地，并以合成验收资料跑通。真实品牌的 6–10 个实拍 / AIGC 镜头及剪映应用实际打开验收仍待完成，不能视为全部验收通过。

## 1. 目标与产品入口

在 GoldenClip 新增“卖货视频创作”入口，让用户在同一项目里上传品牌 PPT、查看创意、获取实拍指导和 AIGC 提示词、回传视频并一键成片。

本方案独立落地，不依赖 OpenMontage。现有 ASR、审计、字幕、渲染和剪映能力按实际接口复用；参考 ForwrdCut 的卖货制作流程和可执行剪辑计划，项目状态与数据由 GoldenClip 管理。

首版默认一个品牌、一个产品、一个主播，制作一条 30–60 秒、9:16、1080×1920 中文视频。用户继续使用自己的 AIGC 工具，平台生成对应提示词并接收结果。

## 2. 现有能力与新增范围

当前 `backend/models/task.py` 的主任务以单个 `video_path` 和片段处理为核心；`task_store.py` 已提供逐任务 JSON、原子写入和版本控制；`jianying_builder.py` 的主入口接收单个源视频及其片段。

这些是可利用的基础，但多文件上传本身不能形成多素材编排，需要新增项目模型和多素材时间线。

参考项目：[ForwrdCut](https://github.com/bussiomedia-sys/forwrdcut)。其 [produce-ad Skill](https://github.com/bussiomedia-sys/forwrdcut/blob/main/.claude/skills/produce-ad/SKILL.md)覆盖广告角度、素材分析、脚本与配音、剪辑计划、渲染和成片检查。借鉴其音频驱动画面时长、镜头服务叙事和可重复渲染的做法，具体模块引入前验证接口与效果。ForwrdCut 不是本方案必须运行的服务，也不能将其文档描述视作已验证能力。

## 3. 用户全流程

### 第一步：建立制作项目

用户选择“卖货视频创作”，上传品牌 PPT、产品图片、主播参考及已有视频，设置平台、片长和主推卖点。品牌资料可跨项目复用，价格与活动信息按本次项目保存。

系统同时读取 PPT 文本与页面视觉内容，整理品牌风格、商品事实及来源，盘点已有镜头。明显缺失且影响创作的信息集中提示，其余内容先完成。

### 第二步：选择创意并拿到可执行分镜

系统提出 2–3 个方向，显示开头、内容结构、核心卖点和预计需要新做的镜头。用户选定方向后进入分镜工作台。

每张镜头卡包含固定编号、预期画面、口播/旁白、字幕、目标时长和剪辑意图，并根据来源显示对应操作：

| 素材来源 | 镜头卡内容与操作 |
| --- | --- |
| 已有素材 | 推荐视频与候选区间，允许替换 |
| 用户实拍 | 拍摄构图、动作、台词和所需余量；回传拍摄视频 |
| 外部 AIGC | 产品及主播参考图、完整提示词、工具参数；复制提示词并回传结果 |

生成提示词时就确定声音归属：主播原声、外部生成对白或独立旁白。产品特写若只作补充画面，默认沿用对应旁白，防止两路对白重叠。

用户修改口播、产品卖点或镜头用途时，系统标出受影响的提示词和素材。分镜的显示内容、复制的提示词和剪辑数据必须来自同一份项目记录。

### 第三步：拍摄、生成、回传

用户可以离开数天再继续。项目保留当前分镜、所有提示词以及每个镜头的完成状态。

首版支持把视频拖入指定镜头卡，同一个镜头可有多个版本。批量上传时可按镜头编号匹配；后续增加画面及台词匹配，低把握结果显示待选择。

系统分析每份素材的实际画面、音频、时长和可用区间。镜头卡显示“可用”“待补充”或“需替换”，并解释具体原因。例如：“S03 已收到，但没有拍到开盖动作，当前素材只能用于产品静态展示。”

### 第四步：一键剪辑成片

必需镜头可用后，用户点击“一键剪辑”。系统根据分镜和实际素材自动完成选段、音画编排、字幕、品牌包装、音乐及导出，直接展示可播放成片。

自动处理停顿、冗余片头片尾和常规时长差异；需要改变已确定卖点或依赖缺失关键画面时，返回具体镜头让用户补充。检查失败的产物不显示为已完成。

新流程将这次点击记录为针对当前方案和素材版本的成片请求，不在内部机械地要求多次重复确认。现有口播精修和直播集锦的人工 review 行为继续按原流程执行。

### 第五步：修改及交付

用户可以替换镜头版本、调整台词或提出“开场缩短”“S02 换为真实拍摄”等意见。系统显示受影响的镜头，生成新版本并保留旧成片。

交付 MP4、字幕与剪映草稿。视频和草稿从同一时间线产生；剪映首版支持多视频、音频、字幕和基础叠加，复杂效果的可编辑范围按实际验证结果标明。

## 4. 数据结构与剪辑依据

新增项目级对象承载跨素材制作，不将它硬塞进原单视频 `Task`。分析单个素材时，可以关联已有任务机制。

| 拟新增对象 | 主要内容 |
| --- | --- |
| BrandProfile | 品牌资料、产品事实、出处、视觉风格与主播参考 |
| ProductionProject | 本次目标、阶段、选定创意、分镜版本、素材版本和导出历史 |
| StoryboardShot | 稳定 shot_id、叙事目的、文案、提示词、参考图、声音安排和剪辑要求 |
| ProductionAsset | 实际文件、指纹、时长、音轨、分析结果、镜头绑定及多个版本 |
| EditTimeline | 画面、音频、字幕、图形轨道，以及源素材区间和成片位置 |
| ProductionRenderJob | 输入版本快照、状态、输出路径及检查结果 |

`shot_id` 连接创作和剪辑，素材版本记录用户实际交回的文件。一个镜头可有多个候选文件，一个文件也可贡献多个区间；使用区间必须显式保存。

规划时长只表达创作意图，渲染时长必须来自实际音频、选定视频区间和最终时间线。裁剪入点、出点须在文件有效范围内，字幕依据最终音频定位。

渲染锁定当前分镜、素材与字幕版本。渲染中发生修改时，当前产物仍归属于旧版本，不能覆盖新版本的结果。重复点击与失败重试复用对应任务记录。

## 5. 模块与接口实施建议

以下均为拟新增设计，具体命名在开发时统一，不表示现有接口已经存在。

| 模块 | 工作内容 |
| --- | --- |
| 资料导入服务 | 提取 PPT 文本、页面图像与图片，形成可追溯品牌资料 |
| 创作规划服务 | 根据资料和素材盘点生成创意、脚本、分镜及逐镜头制作提示词 |
| 素材登记与分析服务 | 管理多文件、多版本、ASR、抽帧、画面匹配和可用区间 |
| 时间线编译服务 | 将确定的分镜与真实素材转换为确定性的多轨时间线 |
| 成片执行服务 | FFmpeg 渲染、字幕和音频处理、取消与恢复、成片检查 |
| 剪映适配服务 | 将同一时间线转为多素材剪映草稿 |
| 创作工作台 | 资料、方案、镜头卡、素材进度及成片版本的统一入口 |

后端可在 `/api/productions` 下建立项目、创意、分镜、素材和渲染接口。耗时工作返回任务标识，通过已有状态推送机制报告进度。前后端共享字段同步定义，项目数据逐项目保存，采用现有原子写入与版本校验方式。

开发涉及 `backend/main.py`、模型、服务、`client/src/lib/api.ts` 和新增工作台页面。单素材分析按适用范围复用现有 ASR 与审计；审计的输出不能直接代替新项目的多轨时间线。业务 Agent 定义放在 `domains/goldenclip/`，通用 `docs/agent-architecture/` 模板保持只读。

## 6. 实施顺序与交付

| 阶段 | 执行内容 | 阶段交付与通过条件 |
| --- | --- | --- |
| B0 关键能力验证 | 使用 3 段来源不同的视频、中文旁白和字幕，验证多素材时间线到 MP4 和剪映 | 两类产物均可打开，顺序、画幅和音画同步正确 |
| B1 项目与资料 | 新增项目存储、品牌资料导入、创建入口和资料页 | 重启后资料仍在，商品事实能够定位到来源 |
| B2 创意与分镜 | 完成创意选择、文案、镜头卡、实拍指导、工具适配提示词 | 任一镜头都能看清制作方式、所需参考和剪辑用途 |
| B3 素材回传 | 实现镜头绑定、多版本、素材分析、等待与恢复 | 分批回传正确更新进度；错误绑定可修正；不丢已有素材 |
| B4 一键成片 | 串接时间线、渲染、检查、取消重试和成片播放 | 一次点击得到真实可播放成片；失败能定位到镜头或步骤 |
| B5 修改与交付 | 局部修订、版本追踪、剪映草稿完善及必要的操作简化 | 换一个镜头可重新成片；草稿在实际剪映版本中验证可用 |

先验证混合素材成片，再逐步完善界面。首版把完整单条视频做通；多个产品、多语言和大量广告变体在完整流程验收后扩展。

## 7. 完成验收

使用真实品牌资料和用户制作的 6–10 个镜头贯穿全流程，其中包含实拍、AIGC、多个素材版本和实际时长偏差。

1. 创意、分镜、提示词、素材与成片始终属于同一个项目，用户不需要再次解释创作意图。
2. 从任一成片镜头可以查到使用的素材区间、镜头文案及原始制作提示词。
3. 等待素材时退出应用，重新打开后按原进度继续；服务重启不会永久显示正在剪辑。
4. 多个版本的素材选取明确；关键镜头缺失时准确提示，不生成假完成结果。
5. 一次点击完成自动剪辑及预览；重复点击、取消和失败重试不会覆盖错误版本。
6. 完整观看 MP4，确认中文字幕、主播声音、产品展示、画面裁切和转场满足方案；检查生成画面是否正确表达产品与主播。
7. 剪映实际打开多素材草稿，验证主要轨道、画幅与音画同步，并抽查与 MP4 的一致性。
8. 现有口播精修、直播集锦、字幕和导出回归通过；前端类型检查、构建及针对受影响链路的有效测试通过。

本方案的主要投入在项目级数据模型、多素材时间线和工作台。价值是日常使用全部留在 GoldenClip，品牌资料、创作和剪辑可以持续积累；它需要比独立流程验证更多的产品开发。

## 8. 首版实施记录（2026-09-19）

### 已实现的入口与模块

- 原任务看板和侧栏新增“卖货视频创作”，入口 `/productions`，工作台 `/productions/:id`。
- 独立模型在 `backend/models/production.py`；API 在 `backend/routers/productions.py`，由 `backend/main.py` 注册。
- `production_store.py` 按项目原子存储、比较版本、保留内容历史及渲染输入快照；重启将中断任务标为可重试。
- `production_media.py` 提取 PPTX 逐页文字、嵌入图片及来源；安装 LibreOffice / pdftoppm 时渲染完整页面预览。产品、主播参考及品牌资料可跨项目复用，本次活动不复用。
- `production_planner.py` 使用已配置模型生成 2–3 个创意及 6–10 个镜头；提示词、拍摄指导和复制内容从同一记录生成。PPT 页面与独立参考图片均可作为镜头参考。
- 素材回传支持拖入镜头、文件名编号匹配、手动重绑、多版本和显式入出点。绑定镜头的视频自动排队进行本地 ASR 与视觉分析；失败保留素材和已完成的语音结果，支持重试或导入 SRT。
- `production_timeline.py` 校验必需素材、音轨、真实字幕、源区间与检查签名；独立旁白会抑制原视频对白。语音前后静默自动收紧，句间长停顿可收紧；连续动作镜头可关闭此选项。音视频与字幕使用同一帧边界。
- `production_renderer.py` 完成竖屏适配、对白响度、中文字幕、品牌文字、可选背景音乐、MP4、SRT 与剪映多轨草稿。包含文件指纹、时长、画幅、音视频流和完整解码检查，失败产物不会作为成片发布。
- 一键剪辑复用同一请求，失败或取消后沿用任务记录增加执行次数；新修改不会覆盖旧快照或旧成片。
- 业务能力定义在 `domains/goldenclip/production.profile.json`、对应 Agent manifest、prompt 和验收契约；通用 Agent 模板未修改。

| PPT 导入 | 合成品牌 PPT 的页面文字、嵌入产品图及 LibreOffice 页面预览成功保存，事实可定位到文件和页码 |

验证素材均为明确标注的合成示例，存放在系统临时目录，没有读取或更改用户原有视频。最后一轮回归：后端 454 项、前端 166 项全部通过，前端类型检查和构建通过。原单视频工作流包含在全量回归中；新制作流程有 15 项后端专项测试和 3 项工作台交互测试。

### 首版边界与仍需完成的外部验收

1. 尚未提供真实品牌的完整 6–10 镜头素材，不能把合成测试等同于商品表达、主播一致性或商业成片质量验收。
2. 本机未发现可用于验收的剪映应用。生成的草稿通过 JSON、多素材轨道和素材时长检查；`jianying_open_verified` 保持 `false`，需在实际剪映版本打开检查字体、位置与音画一致性。
3. 草稿的画面为按最终画幅处理过的镜头，声音、字幕、品牌和音乐为独立轨道；原始源文件名、版本、指纹、区间及制作提示词保存在来源记录。复杂效果不在首版可编辑承诺中。
4. 品牌资料支持 `.pptx`、`.txt`、`.md`；旧版 `.ppt` 需另存为 `.pptx`。AI 创意使用全部已提取文字及前 12 张页面视觉，超长资料的全页视觉分批分析留待扩展。
5. 完整页面预览依赖 LibreOffice 和 pdftoppm；缺失时保留原始图片与文字并显示原因。ASR 复用现有 FunASR 模型，运行依赖已补上 PyTorch / torchaudio。
6. 本地 JSON 项目存储按单后端进程运行；运行数据在 `backend/data/productions/`，已加入忽略规则。公共文件接口只允许访问本项目登记素材和已通过检查的交付产物。
