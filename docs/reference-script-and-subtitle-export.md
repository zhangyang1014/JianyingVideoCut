# 口播原稿匹配与字幕导出

## 使用流程

新建「口播精修」任务时可粘贴原稿，也可在工作台右侧「原稿匹配」补充。识别分段完成后，逐句查看相近录制、重复候选、数字或否定差异，以及匹配候选是否完整保留。点击候选时间可直接试听原声，包括已删除内容。

保存原稿只更新参考信息；再次运行模型语义审计才会影响新的剪辑建议。已有剪辑保持不变。云端和本地 Ollama 审计都会读取相关匹配证据；本地规则引擎不使用原稿决定删除。原稿属于任务内容，模型审计时将发送相关证据给用户配置的模型。

## 匹配边界

- 原稿最多 10000 字；一次比对前 200 句，超出时界面提示。长句拆分为最多 160 字的单元。
- 用双字索引定位候选，再比较最多 6 个相邻 ASR 段组成的窗口；超过 3 秒的空隙不跨段合并。候选文字取实际转写，不使用字幕覆盖层冒充原声。
- 每句最多显示 3 个互不重叠的候选。排序依据字面接近程度，不是录音质量；未匹配可能是漏讲、改述或识别差异。
- 数字表达、否定表达不同，即使字面相似度较高也需核对。合理改述不自动删除，也不按原稿凭空补音。
- 每个模型批次只附相关证据，最多约 6000 字符。原稿摘要纳入审计缓存键，原稿变化后旧审计缓存失效。跨批候选不能成为删除本批唯一完整表达的唯一理由。
- 原稿保存带旧值检查和任务版本检查；任务处理期间不允许修改。未保存输入在刷新比对时保留。

## 数据接口

`TaskParams.reference_script` 保存原稿。新建任务的部分参数与场景默认值合并，避免只填写原稿时覆盖场景的气口配置。

`GET /api/tasks/{task_id}/reference-script` 返回原稿与当前比对报告。

`PUT /api/tasks/{task_id}/reference-script` 接受 `reference_script` 和 `previous_script`，返回保存后的比对报告；版本冲突或处理期间返回 409。

## 字幕导出

FFmpeg 按实际输出顺序将全片 SRT 映射到各连续块的局部时间轴。每块切片时同时缩放、烧字幕、编码，最后直接拼接音视频流，省去整片再次编码。金句前置使用同样的局部字幕投影。

块缓存同时记录局部字幕内容和实际样式；只改一块字幕时，其他块继续复用。没有字幕的块仍可复用原先的无字幕缓存。字幕缺失或格式错误会终止导出，避免生成缺字幕的成片；失败不会覆盖已有完整文件。继续保留取消、临时文件、质量验证和原子发布机制。

字幕滤镜参数依据 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-filters.html#subtitles-1)。
