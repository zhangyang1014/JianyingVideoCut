# 创作者风格分析方法 v1

目标：从一批完整作品中识别创作者反复使用的写法，产出有证据、能写新稿、能继续更新的风格卡。Lina 是第一份实例；换创作者时复用流程，从该创作者的新语料归纳规则。

## 三类产物与入口

| 产物 | 保存位置 | 责任 |
| --- | --- | --- |
| 共用分析方法 | 本文 | 固定选样、标注、统计、复核和更新口径 |
| 版本化风格卡 | `domains/goldenclip/creator_styles/{creator_id}/{version}/card.md` | 给出按题材选择的开场、正文、首答和收尾规则 |
| 证据索引 | 同版本的 `evidence.json` | 保存样本元数据、段落定位、统计口径、规则支持和例外 |

`creator_styles/active.json` 指定各创作者当前使用的版本。新版本另建目录，保留旧版与变更原因。模板见 [证据索引模板](../domains/goldenclip/creator_styles/evidence.template.json)；Lina 初始导入见 [风格卡](../domains/goldenclip/creator_styles/lina/v1/card.md) 和 [证据索引](../domains/goldenclip/creator_styles/lina/v1/evidence.json)。

## 1. 选样与证据边界

先保存分析批次、采集截止时间、创作者与平台账号、原始素材版本和完整性。每条作品记录平台作品 ID、URL、平台创建时间、发布时间、原始时间字段与时区、题材、时长、字幕/音频/视频版本、来源与校验值。缺失值用 `null` 并说明原因，不把下载时间当作品时间。

“最新 N 条”先核对账号，再明确按平台创建时间还是发布时间降序；并列时用作品 ID 固定顺序。保存候选数、匹配数、排除项与理由、实际纳入数、时间区间。候选不足 N 条或时间缺失时报告实际范围。题材分类在逐条标注前约定，允许多标签，跨题材总计须按作品去重。

用完整逐字稿判断段落顺序；缺头、缺尾、节选、字幕漏段单列，不据此断定全片的首答或承诺兑现。识别转载、重发、同源剪辑及同场直播切片，保存 `source_group_id` 与 `recording_id`。分开报告文件数、作品数、独立录制次数；同一录制的不同切片不算独立复现。无法归源时标未知，不能把作品数当录制次数。

多人作品逐段注明 speaker、归属依据和置信说明。只把可归给创作者的话计入其表达习惯；观众留言、主持人和嘉宾的话单列。代述留言属于创作者的开场方式，但留言内容不是其观点。

| 证据 | 可以分析 | 不据此推断 |
| --- | --- | --- |
| 完整字幕/逐字稿 | 脚本结构、用词、句式、承诺与答案 | 实际停顿、重音、语速、镜头及剪辑 |
| 音频 | 上述内容及可定位的停顿、重音、语速 | 镜头、画面字幕及视觉剪辑 |
| 视频 | 可见的镜头、画面字幕、剪辑及实际具备的音频信息 | 未提供的音轨或画外事实 |

每项结论标注实际使用的证据类型与定位。字幕时间戳只是定位；字幕换行不等于口播停顿或功能段落。

## 2. 逐条按功能拆解

先通读全稿，写一句观众主问题，再按功能分段。一个段落可包含多个字幕 cue，也可承担多个功能；指定主功能，保留副功能。功能包括提出问题、交代场景、给判断、给动作、举例、解释原因、说明条件或例外、行动建议、互动和推广。段号从 1 开始，定义变动需重新核对统计。

每段保存段号、功能、时间范围（没有则为 `null`）、简短原文定位词、来源版本和说话人。定位词只用于回查，不用长篇复制原稿。至少逐条填写：

| 标注 | 判断口径 |
| --- | --- |
| 第一段开场 | 直接向观众发问、代述留言、场景、预告收获、先亮观点或其他；分别记录第一段与完整开场的结束段 |
| 观众主问题 | 一句话说明；区分原文明问、场景带出、承诺带出和无法判断；明确问题在何段出现 |
| 第一次实答 | 第一个能直接用于主问题的可执行动作、判断标准或具体解释；记录段号和原文定位。“等会儿讲三个方法”属于预告；无实答记 `null` |
| 正文推进 | 按顺序列功能；每个例子注明演示做法、解释原因或说明例外；识别重复铺垫与话题转换 |
| 结尾 | 逐项核对开场承诺：已回答、部分回答、未回答；记录落在行动、观点、感受或互动，可多选 |

第一段直接提问、完整开场明确主问题、主问题由情境隐含是不同字段。一个片段不能仅因带问号就算创作者直接向观众发问。先给解释也可构成实答，不要求出现编号。没有主问题时说明依据，不强行套“问题—答案”。

## 3. 按题材归纳、统计与复核

先逐条完成，再在相近题材中比较。逐规则写清：适用选题和条件、开场怎么起、正文功能顺序、答案放哪、结尾怎么落、支持作品与段落、反例和边界。规则各有自己的分子、分母与独立录制数；整批有 100 条不代表每条规则都有 100 条支持。题材不足或归源不明时保留为候选。

计数单位默认是去重作品；每条作品对同一规则最多计一次。比例只在字段可判断的作品内计算，同时报告缺失/不可判断数。若报告“100 条中 81 条”，须确认其余 19 条可判，或说明其中哪些未知。段落定位回查次数不能当作规则样本数。报告全部样本结果及按独立录制去重后的结果，无法计算的项留空。

状态：`candidate` 为待验证假设；`reported` 为外部/用户报告、尚未本地回查；`verified` 为本地证据齐全并完成复核。证据状态与写稿建议分开：可采用用户认可的建议，但不能称已从本地样本验证。

复核人回看每条实答和有争议的开场、归属与例外定位，记录复核人、日期、旧标注、新标注、理由。汇总数应能从逐条字段重算；对不上时先保留差异，不修改明细凑数。

样本充足时，可在归纳前留出独立录制组作为验证集，同源切片须在同一组。保存拆分规则及作品 ID，锁定风格卡后才检查验证集。逐规则报告符合数/可判数、未知、失败例子；检查后修改卡须另开版本，原验证集不再宣称独立。没有留出集就明确写未做，不把本批复核叫样本外验证。

## 4. 用于新稿与数字人口播

1. 读取主播受众，写明本次题材、观众主问题、目标时长和可用事实。时长未定时按内容规划，不强行截短。
2. 选适配题材的规则，注明规则 ID；无匹配时按通用功能结构写候选，说明是写稿选择。原样本中的配比、经历、家长留言、产品效果和案例均不自动成为本项目事实。
3. 先写按功能分段的完整稿：开场 → 首答 → 做法/原因/例子/条件 → 收尾。首答的位置按适用规则选择，频率不是所有作品必须遵守的定律。开场有几个承诺，审稿就逐个核对。
4. 润色后复查首答有没有后移、判断与适用条件有没有变化、结尾是否兑现承诺。字幕跟随定稿原意；字幕断行和镜头数不改变口播段落统计。
5. 数字人口播使用同一份定稿，再按段落作用配镜头和 B-roll：演示段配操作，解释段配资料，条件段配对照。音视频节奏是本次制作选择，除非有相应样本证据，不称创作者固有风格。

现有 AI 入口 `backend/services/production_planner.py:plan_with_ai` 给数字人口播注入项目创建时固定的数字人设定、创作者风格卡与证据状态；旧项目尚无副本时兼容读取当前档案。生成方向保存完整 `presenter_snapshot` 与 `style_snapshot`（版本、内容与校验值），模型不能自行填写这些记录。Lina 继续参考结构技能与口播润色，本次明确填写的文字与结构风格优先于冲突的历史建议。普通卖货视频不注入 Lina 卡；已保存的口播转分镜保持原文，不再套风格改稿。模板模式不代表完成风格分析或证据复核。新增数字人在 `/presenters` 管理受众与风格；对应编号尚未注册风格卡时，只使用其自身设定，不继承 Lina 的证据。档案与项目覆盖约定见 [数字人口播工作流](digital-presenter-workflow.md#数字人档案与本次视频设定)。

## 5. 更新流程与验收

新增素材先追加候选批次并去重，记录账号/题材/时间覆盖变化，再依次完成标注、支持/例外核对和统计。原始素材留在本地授权位置，索引只保存可回查引用、版本与必要短定位词，不把用户视频、凭据或大段转写加入源码。

发布新卡前核对：样本和时间口径可复现；规则逐条有支持数、分母、例外与证据类型；未知项可见；验证集没有同源泄漏；当前项目事实与样本写法分开；版本差异说明新增/修改/撤回的规则及原因。保存新版本后更新 `active.json`。未回查的外部摘要保持 `reported`，等待原明细导入，不能凭空补作品 ID、时间或段落。
