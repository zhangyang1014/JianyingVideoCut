# 终止条件与安全边界

自主 loop 必须有明确停止条件。没有停止条件的 agent 不是自主，而是失控。

## 基础终止条件

最少需要四类：

- 最大轮次：避免无限循环。
- 最大消息数或 token 预算：控制成本。
- 文本哨兵：例如 `APPROVED`、`DONE`。
- 外部取消：用户或系统可以中断。

## 目标完成条件

对真实任务，建议再加目标完成检查：

- 是否满足所有显式需求。
- 是否存在未完成 todo。
- 是否调用了 `task_status(status="complete")`。
- 是否有测试或验证证据。

文本“完成了”不是充分证据。

## 失败终止条件

需要防止无效重试：

- 连续 N 次工具失败。
- 连续 N 次没有新信息。
- 计划步骤重试超过上限。
- 模型反复选择同一个无效动作。

失败时应输出 `incomplete`，说明阻塞原因和剩余事项。

## 人工审批点

这些动作建议默认需要审批：

- 删除或覆盖大量文件。
- 运行不可逆 shell 命令。
- 访问生产数据库或生产 API。
- 发送消息、提交 PR、发布部署。
- 修改权限、密钥、配置和账单相关资源。

## 沙箱原则

工具实现要优先限制作用域：

- 文件工具只能访问 workspace 内路径。
- shell 工具设置超时和工作目录。
- 网络工具限制域名或请求方法。
- memory 工具只能访问 memory 根目录。

安全边界应在代码里实现，而不是只写在 prompt 里。

## 结束时输出

每次 run 最好返回：

- `finish_reason`
- `usage`
- `messages`
- `final_content`
- `task_status`
- `open_risks`

这些字段方便上层系统决定是否展示、重试、升级给人类或继续编排。
