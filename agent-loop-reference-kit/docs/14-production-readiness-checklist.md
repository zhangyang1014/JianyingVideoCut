# 上线准备检查清单

上线前逐项检查：

## Agent 设计

- [ ] 每个 Agent 是否职责单一？
- [ ] 每个 Agent 是否有明确“不负责”事项？
- [ ] 每个 Agent 是否强制 JSON 输出？
- [ ] 是否有统一 message schema？
- [ ] 是否有 route policy？

## 状态与通信

- [ ] 是否有 shared state（单一事实源）？
- [ ] 是否有 handoff 机制？
- [ ] 状态是否 append-only（避免并发覆盖）？
- [ ] 是否有 data contract 验证？

## 安全与权限

- [ ] 是否有独立 Validator（Creator 不能自验）？
- [ ] 是否有高风险人工介入机制？
- [ ] 是否有工具权限控制？
- [ ] 是否有安全策略（privacy、compliance）？
- [ ] 敏感 memory 是否需要人工确认？

## 可靠性

- [ ] 是否有 trace log？
- [ ] 是否有失败重试上限？
- [ ] 是否有超时机制？
- [ ] 是否有断路器（连续失败暂停）？
- [ ] 是否有 Saga 补偿（多步失败回滚）？

## 成本与预算

- [ ] 是否有 token 预算上限？
- [ ] 是否有最大轮次限制？
- [ ] 是否有成本监控？

## 评测与迭代

- [ ] 是否有测试用例（正常、边界、高风险、对抗）？
- [ ] 是否有回归测试集？
- [ ] 是否有 prompt 版本记录？
- [ ] 是否有模型版本记录？
- [ ] 是否有回放机制？
- [ ] 是否有回滚方案？

## Memory 治理

- [ ] 是否有 memory write policy？
- [ ] 是否有 memory 过期机制？
- [ ] 是否有 memory 权限控制？
- [ ] 是否有 memory 来源和置信度？

## 数据隐私

- [ ] 是否有数据隐私保护？
- [ ] 敏感信息是否加密存储？
- [ ] 是否有审计日志？
